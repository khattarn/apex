Vapi Architecture — Market-Aware Pricing Injection

Sophie delivers the correct currency to each prospect via Vapi's assistantOverrides.variableValues mechanism. The Vapi system prompt uses {{pricing_line}} (double-brace Vapi syntax) — the value is injected per-call from Python, not hardcoded in the dashboard.

Call flow — how pricing_line reaches Sophie

market="CA"?
→
_pricing_line(market)
→
CAD $70 / $140 / $250 + setup
market=AU/US?
→
_pricing_line(market)
→
$49 / $99 / $180 + setup
place_sophie_call()
→
assistantOverrides.variableValues
→
Vapi {{pricing_line}}
→
Sophie says the right price

Files that implement this

  • helper outreach-agent/agents/click_caller.py _PRICING_USD, _PRICING_CAD, _pricing_line(market) defined at top; CA branch passes pricing_line to place_sophie_call()
  • helper outreach-agent/agents/voice_outreach.py Same _pricing_line() helper; place_outbound_call() passes pricing_line=_pricing_line(market) to Vapi for CA calls
  • param outreach-agent/agents/vapi_caller.py place_sophie_call() accepts pricing_line param; injects into variableValues dict; default is USD string
  • script outreach-agent/scripts/update_vapi_sophie_prompt.py Canonical Sophie prompt — uses {{pricing_line}} in Phase 4 (Trial Offer); run to push prompt to Vapi dashboard
💡
Why {{double-brace}} syntax matters

Vapi uses {{variable}} for substitution. Python f-strings use {variable}. The Vapi prompt stored in update_vapi_sophie_prompt.py uses double-braces so they survive Python string handling unmodified and Vapi substitutes them at call time. The per-call variableValues dict is the source of truth — the Vapi dashboard is just a template with placeholders.
