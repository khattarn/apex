Apex Rebuild Plan — Route A

Fixing the growth engine for PracticeDesk & LegalAidAI. Context of the existing system, what was broken, and what we are now building.
Route A · author-time assets Built in Cowork Wired in VS Code / Claude Code Issued: 2026-06-28

1 · The one-line diagnosis

Apex is two systems wearing one coat. There is a sophisticated, vertical-aware “brain” (Content Agent, VP Marketing, Signal, the mandates) and, underneath it, a frozen “MVP body” (hard-coded dental email templates, a linear pipeline) that is what actually ships to prospects.

The brain produces good drafts that go nowhere automatically; the body sends dental copy to everyone. Most problems trace to one gap: the last mile between the smart layer and the send path was never wired. Route A connects what already exists and adds a guardrail + an approval/monitoring layer — it does not rebuild from scratch.

3 · What was broken (root causes)

The dental→salon bug

The daily job _job_email_campaign calls generate_email(lead), which reads business_type on line 247 and never uses it. Every template is dental, and the salutation is hard-coded to “Doctor”. So a salon gets “Dear Doctor … 73% of dental practices…” — deterministically, every day.

No master prompt

Each agent carries its own ad-hoc prompt; some have none. No shared brand truth, no shared “match the vertical” rule — which is exactly why the email path could go dental-on-salon with nothing objecting.

The brain is orphaned

Content Agent + VP Marketing produce good, vertical-correct drafts — but only via manual endpoints, “not auto-deployed”. vertical_profiles.py (rich pain/objection data) is loaded by no agent. Capability exists; it just isn’t connected.

No oversight & thin monitoring

The CEO agent (founder interface, approvals, kill switch) is 100% stubbed. Alerting catches crashes but not the failures that matter: a job going silent, a job running but sending zero, or a dependency (Resend, Meta, Maps, Anthropic) dying.

Founder/PM read: the system is also spread too thin — 5 verticals × 3 markets × 4 channels, all half-built — so no single funnel gets enough volume to show traction, and broken cold email from the main domain risks deliverability for everything.

4 · What we are now building (Route A)

Route A = use Cowork’s marketing/design skills to produce correct production assets now, then wire them into the live code via Claude Code. No full re-architecture. Five workstreams:

4.1  Vertical-correct email system built here

The headline fix and the founder’s priority (“the hook has to be good”). A new email_copy.yaml holds one sequence per vertical (dentist, physiotherapist, salon, accountant, lawyer) + a safe generic fallback — 20 emails, each with two A/B subjects, a preheader (the inbox hook), a grounded body, and a P.S. Every claim comes from the brand brief; positioning is always “across phone, WhatsApp and email”; sign-off is Henry. The 4-email arc per vertical:

Day 1  Hook      vertical-specific pain, named in the subject + preheader
Day 3  Test      a concrete 30-second self-test the reader can run today
Day 6  Proof     the lead stat + how it works + pricing
Day 9  Break-up  top objection handled + soft close + last email

Deliverables in this folder: email_copy.yaml (the asset) and sample-emails.html (a visual preview of all 20).

4.2  Master prompt + per-agent prompts & skills built here

One shared master prompt (org identity, two products, brand non-negotiables, the vertical-match rule, oversight, compliance, focus) inherited by every agent, plus a specific prompt and a Claude skill set per agent. Vertical stays configuration, not a separate agent.

4.3  CEO / Founder daily loop built here wired in VS Code

The CEO agent becomes a daily growth operator until traction exists: read yesterday’s events → diagnose the biggest funnel leak → report a one-page brief → propose 1–3 cheap, reversible experiments → wait for one-tap approval → measure yesterday’s bets. Composed from the Small Business “owner cockpit” briefing pattern + performance-report + campaign-plan.

4.4  Monitoring & founder intimation wired in VS Code

Three new detectors on top of the existing crash alerter: a heartbeat / deadman’s switch (catches silence), threshold alerts (catches “ran but sent zero”), and dependency probes (names which service is down and why). Every intimation goes to both WhatsApp and email.

WhatsApp constraint: Meta only allows business-initiated messages outside the 24h window via approved templates. So founder alerts need two UTILITY templates — apex_daily_brief and apex_system_alert — while email is the always-on fail-safe (and survives a broken WA token, which the current single-channel alerter does not).

4.5  Vertical-as-config principle enforced in VS Code

No vertical-specific agents. Agents stay function-specific and take business_type / product as input, pulling behaviour from config (copy.yaml, email_copy.yaml, vertical_profiles.py). Fixing the dental→salon class of bug structurally, enabling shared learning, and making a new vertical a row of config rather than a new bot.

4.6  Per-market channel re-ranking built here wired in VS Code

See channel-strategy.html. WhatsApp is a minority channel in US/CA/AU (US ~23%, AU ~33%, CA lower); email is what B2B buyers prefer. So the funnel becomes email (engine) → engagement-triggered Aria voice call → WhatsApp for booking (post-opt-in), with a separate low-volume CASL-safe track for Canada. This is Change #6 in the handoff — it stops effort being spent on a minority cold channel and removes the Canadian legal risk of one-size-fits-all blasting.

6 · Division of labour

built here  Cowork (this workspace)

  • Master prompt + all per-agent prompts
  • Skill-generated assets: email_copy.yaml, copy.yaml refreshes, sequences, wedge plan
  • The two WA founder-template texts
  • The monitoring/health spec
  • This reference document + the Claude Code handoff prompt

Why here: the marketing/design skills only run in Cowork. Assets are portable — their substance can be baked into agent prompts so the deployed system needs no chat.

wired in VS Code  Claude Code (the repo)

  • Make generate_email vertical-aware; load email_copy.yaml
  • Drop in prompts; add the master-prompt preamble + pre-send guardrail
  • Build heartbeat + thresholds + dependency probes; dual-channel alerts
  • Submit the two WA templates to Meta; set Railway env
  • Test against live Supabase/Resend/Meta; deploy to Railway

Why there: git, secrets, live services, Meta submission, and Railway deploy all live in the repo.
