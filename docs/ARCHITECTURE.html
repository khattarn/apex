Call Recording & Webhook FIXED 2026-06-30

Vapi End-of-Call Webhook
Endpoint: POST /api/webhooks/vapi on Railway
Event type handled: end-of-call-report only. All other event types return 200 and are ignored.

Outbound (Sophie): updates lead status → replied, logs outbound_call_completed with ended_reason, recording_url, summary, transcript.
Inbound (Henry): phone-lookup match → logs inbound_call.
⚠️ Critical: serverUrl must be top-level in Vapi call payload
serverUrl must be a top-level field in the Vapi call creation JSON — NOT inside assistantOverrides.
Placing it inside assistantOverrides is silently ignored by Vapi and end-of-call webhooks will never fire.

Correct structure in vapi_caller.py → place_sophie_call():
"serverUrl": "...",  ←  top-level
"metadata": {"lead_id": lead_id},
"assistantOverrides": { "variableValues": {...} }
lead_id in metadata
Each Sophie call includes "metadata": {"lead_id": "..."} in the Vapi payload.
The webhook handler reads call.metadata.lead_id to identify the lead without a phone lookup.
Fallback: phone-based lookup via _find_lead_by_phone() if metadata is missing.

Known Open Issues

Vapi concurrency limit — 10 concurrent calls ISSUE
The hourly cron fires all queued leads simultaneously. When more than 10 calls try to start at the same time, Vapi returns "Over Concurrency Limit". The calls that hit the limit are not retried — they're logged as errors in that cron run and will be picked up next hour. Mitigation: stagger calls with a small delay, or reduce batch size below 10.
Dograh India — Vobiz "from number not owned" error ISSUE
